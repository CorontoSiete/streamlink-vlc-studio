# Kick live clipping

Select a live Kick tab and click **Clip**. The app creates and publishes the latest 30 seconds in the background with a channel-and-timestamp title, then opens the confirmed public clip in the default browser. There is no editor window or browser audio. The app status bar reports progress and errors.

Sign in once through **Detect Kick follows** in Settings. The background browser shares `%LOCALAPPDATA%\StreamStudio\KickFollowsWebView2` with follow detection. Website sign-in is separate from the Kick OAuth credentials under Accounts and from the default browser's sign-in. **Clear Kick sign-in** in follow detection clears this shared session. If sign-in expires or Kick requires a browser check, the status bar directs you back to Detect Kick follows. Playback media is allowed for the hidden editor but always muted; the follow importer still blocks media. VOD clipping is outside this change.

## Verified sources, 2026-09-26

- [Kick's clipping guide](https://help.kick.com/en/articles/7120566-how-to-create-clips-on-kick) documents signed-in creation, the editor, Publish, 10–180 second clips, and the cooldown/channel restrictions.
- [Public API documentation index](https://github.com/KickEngineering/KickDevDocs/blob/main/SUMMARY.md) and [Swagger](https://api.kick.com/swagger/doc.json) contain no public clip-creation endpoint. OAuth clipping scopes were not invented.
- The [Kick channel page](https://kick.com/xqc) loaded [player events](https://assets.kick.com/main/_next/static/chunks/21x1o_1_9c2ad.js), which define `openClipCreator` and accept `{mode:"livestream"}`. The [editor provider](https://assets.kick.com/main/_next/static/chunks/2oks7dlrkrtd_.js) resolves that command against the current channel's source. It selects the internal or web backend using Kick's own feature flag.
- That provider initiates internal live drafts with `POST /api/internal/v1/livestreams/{streamSlug}/clips` and finalizes with `POST .../clips/{clipId}/finalize`. Both responses expose `id` at the root. The stream slug belongs to the live session, not necessarily the channel name.
- The [web clip client](https://assets.kick.com/main/_next/static/chunks/16e0adqhzcp69.js) uses `POST /clips` and `POST /clips/{clipId}/finalize`. The [fetch implementation](https://assets.kick.com/main/_next/static/chunks/3f4a4e01ll_c0.js) prefixes `/api/v1`; the [environment](https://assets.kick.com/main/_next/static/chunks/24vax2xd1yhg9.js) sets its origin to `https://web.kick.com`. Responses expose `data.id`.
- The site's [URL helpers](https://assets.kick.com/main/_next/static/chunks/09ldydz755y53.js) construct public links as `https://kick.com/{channel}/clips/{clipId}`.

These asset filenames identify the source inspected, not runtime dependencies. The application invokes the website editor and observes its responses; it does not reproduce private POST calls. The bridge tracks the editor event listener being mounted/removed, checks the selected channel, and waits at most 30 seconds for readiness. The same provider bundle defines a default 30-second selection at the end of the draft and the `clip-creator-title` and `clip-creator-publish` test IDs. The app fills that title control through native input events, waits for the form to enable Publish and for a verified draft, then clicks Publish exactly once. It never retries publication automatically. If Kick changes its editor contract, the user sees a readiness/verification failure rather than a fabricated success.

Publication verification only accepts HTTPS on the exact verified hosts, POST to the verified live routes, and a finalization request matching a successful draft from this page. The public ID comes from the final response, as in Kick's editor; it need not be identical to the draft ID. Bodies are bounded to 256 KiB and draft tracking to 32 entries. Navigating away invalidates pending results. The native host is never shown or activated. Creation is bounded to two minutes; completion, failure, cancellation, or shutdown closes the controller and host, including controllers that finish initializing after cancellation. No cookies, authorization headers, or response bodies are logged or stored in settings. Kick validates the title, duration, permissions, and cooldown.

## Validation

`KickClipTestCatalog` covers both response contracts, malformed/unconfirmed/mismatched results, URL restrictions, HTTP errors, selected-tab command routing, cancellation, shutdown, and browser-launch failures. Real WebView2 tests use an isolated profile with every request intercepted locally to exercise script readiness, title entry, automatic publication, response observation, and preview media. Background-service tests verify the native host stays hidden, audio is muted, publication happens once, sign-in and API errors propagate, and cancellation cleans up both active and late-created controllers.

Silent-creation validation: the Release build has zero warnings/errors and all 12 clipping tests pass. Formatting checks pass after correcting a line ending. The full headless suite recorded 1,192 passed, one failed, and 246 skipped; the existing `opening Kick VOD resolves HLS tab without recents` test failed at its seek-enabled assertion and passed on an isolated rerun. Its code was not changed.

An additional read-only smoke check against the live Kick website on 2026-09-26 confirmed that the current editor listener mounts and that dispatching the command on a live channel opens Kick's sign-in dialog in a fresh WebView2 profile. Clip mutation requests were blocked in that diagnostic, and no public clip was created.

Authenticated end-to-end publication still requires a real Kick sign-in and a live stream. Synthetic browser fixtures validate the integration, not a successful publication against a particular Kick account.
