# Player navigation

The browser watch toolbar and stream tabs are removed. Video and docked chat begin directly below the main header, without a reserved toolbar gap. Each player?s playback gear menu contains a Multi-stream switch above Quality and Speed. Turning it on shows all open players; turning it off keeps the player whose menu was used. Every menu reflects the shared layout, including newly opened and reloaded players. Selected-stream audio and inactive-player pause preferences keep their existing behavior. The player?s fullscreen button opens the grid when Multi-stream is enabled; changing the switch while fullscreen transfers fullscreen to the corresponding grid or selected-player view.

Following contains the open players first. Green names, avatar dots and explicit Watching/Open/Stopped text identify their state; the selected player has an additional green edge. Each open row has its own sibling exit button. Clicking that exit preserves the current selection when closing a background player. Closing the final player returns to the library.

Multi-stream reserves the viewport below the header for video rows. The former 36vh video cap is removed; video fits its tile without cropping. All channel information follows the final video row, including with an odd number of players, so bios and panels require scrolling and cannot shrink or separate the videos. Narrow screens use one column and account for the bottom navigation. Tiles keep a 180px minimum height when many streams are open, allowing the page to scroll. Overlay chat stays inside its video, docked chat shares the media tile, and fullscreen uses the full viewport. Switching back to a single player restores its original watch-page layout without replacing video or profile elements.

Open channels replace their ordinary followed row, which returns after closing. Unfollowed channels remain reachable, and separate videos from the same channel receive distinct rows with video titles and exit labels. Reopening the same library key selects the existing player. Reloading replaces the player row without losing its name or creating stale controls.

At phone/tablet sizes, and in theatre mode, the existing main header contains a Following button that opens a native modal containing the same channel list. Its exit buttons have 44px targets. Native Escape and backdrop dismissal restore the list to the sidebar; closing and immediately reopening cannot deliver the previous close event into the new dialog. On phones the header uses a compact brand icon while watching so stream navigation stays reachable. Narrow video containers use compact playback controls and open the gear menu below them, clear of the fixed header. Long channel names wrap in the profile area. The brand link returns to the library; Following rows and Stream options retain their close actions. The configurable Back shortcut (Escape by default) now retraces page navigation; see [web keyboard shortcuts](web-hotkeys-2026-10-23.md).

Run the dedicated Chromium regression with:

```powershell
node scripts/tests/web-navigation.browser.cjs
node scripts/tests/web-navigation.browser.cjs --multistream-only
```

It uses the actual production HTML/CSS/JavaScript with deterministic API data and a real decoded HLS fixture. It dispatches browser pointer and keyboard events, checks switching, independent exits, duplicate prevention, live/video/unfollowed rows, grid audio selection, rename/reload, Multi-stream pointer and Space-key operation in both grid tiles, switch synchronization after open/reload, fullscreen layout changes, theatre access, drawer dismissal, final-close focus recovery, toolbar removal, menu bounds, and overflow at 11 watch widths from 320 to 1920 pixels. Screenshots and viewport measurements are written to `.artifacts/player-navigation/`. Set `SVS_WEB_TEST_BROWSER` to select a Chromium executable; installed Windows Chrome/Edge are detected by default. This fixture does not verify production TLS or live provider availability.

The existing HTTPS WebView2 tests retain real authentication, playback, volume, overlay and responsive-library coverage. Their stream switching uses Following and layout checks use the gear-menu switch. The overlay grid test opens two distinct channels because reopening a library entry selects its existing player, and dismisses the saved-preferences notification before dragging handles that it would otherwise cover.

The dedicated multi-stream check decodes the existing 16:9 HLS fixture, measures media and profile positions at the supplied screenshot's 1910x965 viewport, scrolls to descriptions with actual wheel input, and covers 1-16 players, long bios, odd counts, chat layouts, fullscreen, selection/audio, responsive widths and closing back to one player. It writes screenshots and `measurements.json` to `.artifacts/web-multistream/`. At that viewport, the original video height was 347.39px; the corrected 16:9 picture is 464.91px tall inside a 901px media tile, and channel information starts at y=967, below the viewport. Panel column changes are scheduled on the next animation frame to avoid resizing their observed region during ResizeObserver delivery.
