# Uninstall and automatic update cleanup

The ZIP uninstaller now passes the selected personal-data policy to its staged process. Previously, `--preserve-user-data` was lost during handoff because the child defaulted to removing data. Both quiet and interactive handoffs are covered by regression tests.

After removal, a hidden cleanup process waits for the staged uninstaller to exit, removes its executable and handoff token, and removes the empty stage directory. It validates the exact temporary directory, rejects reparse points, and preserves unexpected files. Cleanup only starts after the uninstall handshake was validated. The running stage is excluded from personal-data cleanup so its locked executable does not incorrectly report an incomplete uninstall. Reboot cleanup remains a fallback if the cleanup process cannot start.

The updater now cleans its cache at startup independently of network checks and update preferences. It removes packages for installed or older versions and removes superseded packages after a replacement is verified. Failed replacement downloads preserve the previous package; failed or canceled installations remain retryable within the seven-day retention window. Existing retention limits for abandoned downloads and logs still apply.

File traversal and startup deletion retries run outside the UI thread. Partially deleted operations are marked for retry, using the directory timestamp API for directories. Deletion validates ancestor paths and cannot traverse cache junctions. Settings and files outside the update cache are preserved. Existing MSI upgrades and atomic ZIP replacement continue to remove obsolete managed application files.
