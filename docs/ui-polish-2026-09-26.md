# UI polish and verified fixes

This pass builds on the existing grey and green redesign. Home now has a compact
search header, clearer library and page headings, slightly larger body text, and
consistent 16:9 live and VOD previews. Thumbnail height is measured before card
rows are arranged, including when cards fill the available width. Keyboard focus
is visible on cards and history actions; text and password fields keep their
content in place when the focus outline appears. All eight palettes are retained.

The following behavior was reproduced before changing the implementation:

- Switching from a scrolled Hotkeys page to Accounts inherited a 359-pixel
  offset, hiding the new page's heading. Changing categories now resets both
  settings viewers. A subsequent focus or BringIntoView request takes priority,
  keeping Save and other controls reachable in compact windows.
- Save failures updated an undisplayed status property. The settings footer now
  shows saving, success, cancellation, and failure feedback in wide and compact
  layouts. A failed or canceled save releases the command for retry. Cancellation
  still propagates to command callers.
- Search results remained open when navigating to Settings, and Escape did not
  dismiss them. Leaving Home, entering Settings or fullscreen, and pressing
  Escape now close the dropdown. Dismissal retains the query and verified
  results; pending automatic searches cannot reopen the dismissed dropdown.

Search also has a labeled Clear button that empties the query and cancels pending
results. The settings save confirmation has its own state, so background stream
status updates cannot replace it.

Seven `studio polish:` regression cases cover category scrolling, visible save
failure and retry, pending and canceled saves, search navigation, Escape, clearing
search, and card proportions and scroll reachability. The first four checks were
run against the previous implementation and failed before the fixes.

Validation commands:

```powershell
.\scripts\dev.ps1 Check -ExpectedMaxSkips 250
.\scripts\dev.ps1 Test -NoBuild -Interactive -Filter 'responsive'
.\scripts\dev.ps1 Test -NoBuild -Filter 'studio shell:'
```

The full Check passed formatting, PowerShell/tooling checks, native dependency
verification, a Release build with zero warnings or errors, and all 1,226
headless tests (250 expected desktop skips). All 26 focused desktop checks passed
with zero skips. The shell render also passed and all eight palettes were
visually reviewed.

The baseline contained 1,219 passing headless tests and 250 cases explicitly
skipped because they require a desktop. The baseline's only failure was its
outdated skip ceiling. The explicit 250 ceiling above matches that audited
inventory; the new regression tests require no desktop and add no skips.

Focused desktop runs additionally cover the shared theme, dropdown hover, tab
selection, navigation selection, toolbar toggles, detached-player theme changes,
VOD progress indicators in dark and light themes, and physical hover previews.

Local logs, original-source snapshots, and rendered PNGs are retained under
`.tmp/ui-modernization`. An isolated review host used the production window and
fake services; no account settings were loaded. Windows capture failed with
`SetIsBorderRequired` (`0x80004002`), so visual review used production WPF renders.
The running host's accessibility tree confirmed search results and Escape
dismissal without clearing the query.
